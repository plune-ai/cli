# Spec — C5-run-commands

> **Епік:** `plune-ai/plune#486` (B-2) · **Сусіди:** [`C1-reporter-core`](../C1-reporter-core/spec.md), [`C4-reporter-env`](../C4-reporter-env/spec.md)

## 1. Context

Репортер закриває прогін, коли один процес виконав усі тести й знає, що вони скінчились. Є випадки,
яких він **не бачить**: шарди як окремі кроки CI, стадія `merge-reports`, набір, поділений між двома
раннерами. Хтось має відкрити прогін до того, як почнеться перший, і закрити після останнього — і цей
хтось є командою в шелі.

Один із цих випадків уже став обіцянкою: C1 друкує `plune run finish <id>` для прогону, який лишили
відкритим. **Повідомлення, що вказує на неіснуючу команду, гірше за відсутність повідомлення.**

Другий борг того ж роду — fallback-файл. C1 каже «нічого не губиться», а на ділі результати лежать
на диску у формі, яку ніхто не читає. Це не те саме, що не загубити.

## 2. Goals

1. `plune run start` — відкрити або приєднатися до прогону за ключем, надрукувати id.
2. `plune run finish <id>` — закрити (або `--terminate`) — та сама команда, яку радить репортер.
3. `plune run exec -- <cmd>` — усе в один рядок: відкрити, виконати, закрити.
4. `plune run report` — відправити те, чого репортер не зміг.

## 3. Non-goals

- **`--playwright-json` / `--junit`** — імпорт готового звіту раннера. Це друга половина C5 і
  окремий парсер на формат; лишається наступним кроком, а не мовчазним пропуском.
- Поля прогону з D13 (`title`, `env`, `labels`) — зміна платформи.
- Заміна репортера. Ці команди — для того, чого репортер не бачить, а не замість нього.

## 4. User stories

- **US-01:** Як інженер CI, я відкриваю прогін окремим кроком і передаю його id шардам.
- **US-02:** Як інженер CI, я закриваю прогін після `merge-reports`.
- **US-03:** Як інженер, я обгортаю свій запуск у `plune run exec` і не думаю про життєвий цикл узагалі.
- **US-04:** Як інженер, я бачу відкладені результати після того, як бета була недоступна, і надсилаю їх.

## 5. Acceptance criteria

| # | (US) | Критерій |
|---|---|---|
| AC-01 | US-01 | `run start` шле `schemaVersion: 2` з ключем; 201 → «Started», 200 → «Joined» |
| AC-02 | US-01 | Без `--key` ключ генерується — інакше `exec` не мав би що передати дитині |
| AC-03 | US-01 | `--json` друкує один машинний рядок |
| AC-04 | US-02 | `run finish <id>` надсилає подію; `--terminate --reason` — іншу |
| AC-05 | US-02 | Відмова платформи переказується дослівно: 409 несе перелік дозволених переходів, і саме він відрізняє «спробуй ще» від «цей прогін уже закрив merge-крок» |
| AC-06 | US-02 | 404 називає ймовірну причину — чужий проєкт токена, а не лише «не знайдено» |
| AC-07 | US-03 | `exec` передає дитині `PLUNE_RUN` і `PLUNE_PROCEED`, щоб репортер усередині **приєднався** й не закривав |
| AC-08 | US-03 | `exec` повертає код команди, не свій |
| AC-09 | US-03 | `exec` закриває прогін **навіть коли команда впала**: невдалий прогін усе одно завершений, а відкритий казав би «ми так і не дізнались» |
| AC-10 | US-03 | Порожня команда відхиляється **до** відкриття прогону |
| AC-11 | US-04 | `run report` повертає готовий батч у той прогін, для якого його писали |
| AC-12 | US-04 | Батч, який до прогону не доїхав, відкриває прогін і резолвиться — але **не закривається**: реплей не знає, чи прогін повний |
| AC-13 | US-04 | Файл лишається на місці. Частково невдалий реплей не має бути причиною, чому зникає решта |
| AC-14 | US-04 | Відмову рахують як невідправлене, а не як надіслане |
| AC-15 | — | `plune run` без підкоманди працює як раніше — він не має позиційних аргументів, тож нічого не змінює значення |

## 6. Non-functional requirements

Холодний старт: усі обробники імпортуються **всередині** дії (правило `cli.ts`), тож
`plune --version` не платить за них нічого.

## 6.1 Security / privacy

Токен береться тим самим ланцюжком, що й скрізь: явний → `PLUNE_TOKEN` → сховище `plune login`.
Ніколи не друкується.

## 7. Test plan

Юніти на кожен обробник із інʼєкцією `fetchImpl` і `spawnImpl` — той самий шов, що в C1, тож
жодного процесу й жодної мережі. Плюс перевірка на беті: `run start` → `run finish` → `statusEvent:
finished`.
